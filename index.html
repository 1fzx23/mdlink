文档里的断链，
不该等到读者点开才发现。

改个标题，「安装步骤」的锚点就全废了；挪个目录，相对路径全 404； 在自己电脑上一切正常，推到 GitHub 却打不开 —— 因为大小写。 mdlink 一条命令把这些全查出来，还告诉你该怎么改。

查看源码 → 先看怎么用

为什么不是又一个链接检查器

大部分工具只联网确认 URL 能不能打开。写文档时真正坑人的不是那件事。

🎯

锚点按 GitHub 规则重算

小写、去标点、空格转 -、重复标题加 -1。中文标题也认，## 快速安装 → #快速安装。

🔠

专查「本地能跑，上线 404」

Windows 和 macOS 文件名不分大小写，Git、Linux 分。逐段比对磁盘真实名字，提前拦住 docs/API.md 这种坑。

🧹

不把示例代码当真链接

围栏代码块和行内代码先被遮罩成等长空格，[示例](foo.md) 这种教学写法一条都不会误报。

🔌

默认一个请求都不发

只有加 -x 才联网。CI 里跑结果完全确定，不会因为网络抖动忽然变红。

💡

直接给修复建议

锚点写错，告诉你最接近的是哪个；文件名拼错，告诉你是不是 xxx。不用自己翻目录找。

📦

单文件零依赖

一个 mdlink.py 就能跑，Python 3.9+，不需要装任何包。

能查出的问题

断链会让命令以退出码 1 结束，警告只提示、不影响 CI。

类型级别含义
missing-target断链路径指向的文件不存在
missing-anchor断链目标文件里没有这个 #锚点
empty-dest断链[文字]() 目标为空
case-mismatch警告大小写与磁盘实际文件名不一致
dir-target警告链接指向目录（需 --dirs）
http-status断链 / 警告外链 404 为断链，其余 4xx/5xx 为警告
unreachable警告连不上：DNS / 超时 / SSL / 被墙

用法

克隆下来直接跑，或者 pipx install . 装到 PATH。

# 扫当前目录所有 Markdown
mdlink .

# 只查指定文件 / 目录
mdlink README.md docs/

# 顺便探测外部链接（12 并发，8 秒超时）
mdlink . -x

# 出 HTML 报告
mdlink . -f html -o link-report.html

# 忽略本地开发地址
mdlink . -x --ignore "localhost|127\.0\.0\.1"

# 不确定锚点怎么写？问它
mdlink --list-anchors docs/guide.md

输出格式支持 text / json / md / html；退出码 0 通过、1 有断链、2 参数错误。

接进 CI

PR 里改坏了文档链接，直接让流水线红掉。

# .github/workflows/docs.yml
name: docs
on: [push, pull_request]
jobs:
  links:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - name: 检查文档链接
        run: python mdlink.py . --no-color
